# rustyAC v1.1.5

No Visual C++ runtime to install any more, and online name tags show the server's driver names.

## What's in it

- **No VC++ runtime needed** ([docs/csp/core.md](https://github.com/thesupersupersigma/rustyAC/blob/v1.1.5/docs/csp/core.md), C5i-c):
  the C runtime is now built into `rustyac.exe` and `rustyac-launcher.exe`, so both start on a clean
  Windows install without the Visual C++ redistributable. They load only Windows' own DLLs.
- **Online name tags** ([docs/csp/assettoserver.md](https://github.com/thesupersupersigma/rustyAC/blob/v1.1.5/docs/csp/assettoserver.md), NH-1):
  other drivers' name tags and the tables read "Driver N" online, Kunos servers included. They now
  show the names the server sends.
- **A bigger exe**: `rustyac.exe` is about 30 MB (it was 12 MB). Most of that is Embree, the ray
  library CSP casts its tyre rays with, plus the built-in C runtime. Embree is only used by the
  experimental CSP core below. Vanilla's physics never calls it.
- **CSP's own physics core, as an experimental switch** ([docs/flags.md](https://github.com/thesupersupersigma/rustyAC/blob/v1.1.5/docs/flags.md)):
  `--csp` (or `[CSP] ENABLED=1`) is the same as in v1.1.4: CSP's data on Assetto Corsa's own physics.
  `--csp --csp-core` (or `[CSP] CORE=1`) runs the port of CSP's own core instead. It matches CSP
  step for step up to the tyre step, which is the next work (C5j), so it is not CSP-exact yet. Cars
  and tracks it can't run yet stay on Vanilla's core and say why, in the game's banner and its log:
  strut suspensions, cars with a zero-sided collider box, and tracks with loose objects. Replays
  record the switch, so a replay plays on the core it was driven on.

## Known gaps

- CSP's own core differs from CSP from the tyre step on, so it stays behind `--csp-core` until it
  is identical.
- The launcher has no CSP line. CSP mode is set in `cfg\rustyac.ini`, and a refusal shows in the
  game's banner and log, not before the race. The browser has no CSP mode.
- The rest is as in v1.1.1.
